# AGENTS.md 全文模板（ch5 章交付物二）

> 用法：把下面「模板全文」代码块原样复制到你项目根目录的 `AGENTS.md`，
> 再把四个尖括号占位 `<...>` 换成你自己项目的值。每段前的 HTML 注释是逐段解释，
> 抄进项目时可以整段保留（AI 代理会忽略注释）也可以删掉。

## 模板全文

````markdown
# <项目名> — 工作约定（供 AI 代理）

<!-- 【整体】AGENTS.md 是给 AI 编码代理（Codex / Claude Code 等）看的说明书，
     代理每次进项目都会读到它。写法只有一条原则：把你会当面叮嘱一个新同事的话
     写下来，不加修辞、不写愿景。全文控制在几十行内，超长的代理不会记住。 -->

<!-- 【角色】第一段说清项目是什么、代理这次要做什么。AI 最常见的失控是自作主张
     换方案、顺手"优化"范围外的代码，所以这里要写死边界：范围外的问题记下来
     停下来问人。 -->
## 角色

- 本项目是 <一句话定位，例如「零基础读者的第一个 Harness 实验田」>。
- 你的任务范围是 <本次要交付什么>；范围外的问题记录下来停下来问人，不要自行扩面。

<!-- 【铁律】第二段是不可违反的硬约束。每条都要能机械判真伪——能跑一条命令、
     能 grep 一个词来验证；写不出来的约束（"代码要优雅"）代理守不住，等于没写。 -->
## 铁律

- <约束一：例如「测试先行：先写失败测试，确认红，再写实现，确认绿」>
- <约束二：例如「依赖版本一律钉死在版本文件里，不引入版本文件之外的库」>
- <约束三：例如「实验代码只进 experiments/ 目录，不混入 src/ 正式区」>

<!-- 【验收命令】第三段回答"怎样算做完"。把能一键跑的验收命令给全，
     代理会自己跑、自己修；没有可跑命令的验收条款等于没有验收。 -->
## 验收

```bash
<安装依赖命令，例如 npm install --registry=https://registry.npmmirror.com>
<构建门命令，例如 npm run build>
<测试门命令，例如 npm test>
```

<!-- 【目录约定】第四段告诉代理每类文件放哪。AI 对"临时件放哪"没有天然直觉，
     不写它就会把调试脚本和正式代码混在一起；约定临时目录整体不入库最省心。 -->
## 目录约定

- <正式代码目录，例如 src/> —— <什么放这里>
- <实验/草稿目录，例如 experiments/ 或 _work/> —— <什么放这里，以及它不入库>
- <文档目录，例如 docs/> —— <什么放这里>
````

## 四段为什么是这四段

- **角色**约束代理"做什么"——没有它，代理会把 adjacent 的工作也顺手做掉。
- **铁律**约束代理"不许做什么"——每条可机械验证是它和口号的区别。
- **验收命令**定义"做完"——代理的循环是改代码、跑验收、按输出修，命令给全它就能自转。
- **目录约定**回答"文件放哪"——缺了它，临时件必然污染正式区。

这四段与 ch5 双臂实验是同一件事的两个尺度：实验里我们给候选一段规约加一套断言；
AGENTS.md 是把"规约+断言"装进任何项目根目录的最小模板。
